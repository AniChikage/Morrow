# Morrow 的理论依据与可验证机制

研究日期：2026-09-08。用户希望引入先进理论指导框架，并建议把神经科学进展作为参考。本文是经过来源核对的工程研究与候选设计，不代表用户已逐项确认这些方案，也不代表下面的新机制已经进入运行时。

当前实现基线是 0.8.0：在 0.7.1 的项目认识、候选行动、原始预期、反馈唤醒、词面经验召回与适用性引用上，增加预先约定的观察窗口/来源、逐项结果与约束核对、原因和调整层次，以及认识修订引用。持续遵循 [产品方向](PRODUCT-DIRECTION.md)。理论用于提出可以被证伪的工程假设；人提供目标、资源与授权，具体策略继续由 Codex 形成。

## 总体判断

神经科学适合帮助我们理解有限记忆、经验泛化、预测落差与策略调整。决策论用于判断下一步行动或继续思考是否值得；因果推断用于判断结果能否归因；Agent 研究提供可执行经验复用的工程参照。开放式搜索、时间抽象、组织学习与黑板架构进一步帮助设计问题发现、长期推进和工作协调。这些来源需要一起使用。

采用某项理论前，先明确它解决的故障、能改变的具体机制，以及相对现有版本的验证方式。脑区命名、角色数量、反思文本长度和技能数量都不构成效果证据。论文里的动物实验、人的受控任务、计算模型、LLM 基准与真实项目经营，属于不同证据层次。

## 1. 情节记忆与一般知识：保留事实，谨慎概括

**来源与边界。** Spens 与 Burgess 于 2026-06-25 发表计算模型，用压缩、检索与巩固解释情节和语义记忆的相互作用，也展示了记忆向既有预期偏移的失真。这是计算建模，并非已证明大脑就是 RAG。模型中的巩固涉及网络训练；Morrow 的外部记忆机制不等同于更新 Codex 权重。[原论文](https://www.nature.com/articles/s41467-026-74357-6)

**工程提案。** 分别保存实际事件、由事件归纳的候选规律、可执行的方法。实际输入输出和观测保持原样；规律附带依据、适用范围、反例和版本；方法附带前置条件、验证与停止条件。摘要是可重建索引，不能成为原始证据的替代品。多次引用同一来源不算多次独立验证。

**怎样验收。** 在多条表面相似、条件不同的经历中，检查模型能否保留例外；刻意提供一条误导性概括，验证它是否回读原始证据。比较仅存摘要、存原文加摘要、再加入经验证规律三种方式的错误率、检索成本与后续表现。巩固引入的错误也必须计入。

**现状。** 原始证据、记录版本与摘要已具备；跨经历概括及其独立验证尚未形成子系统。

## 2. 内容与情境分开表达：相似不等于适用

**来源与边界。** 2026 年一项人类单神经元研究在 16 位接受侵入式监测的患者、受控图片比较任务中，观察到内容与任务情境主要由不同神经元群表示，并通过共同活动结合。它为情境化检索提供依据，但不能直接证明某种数据库结构最优。[Bausch 等，Nature](https://www.nature.com/articles/s41586-025-09910-2)

**工程提案。** 经验既描述“做了什么”，也明确“在什么条件下成立”：项目阶段、版本、样本、使用场景、资源和约束。字段按实际需要形成，不要求填满统一表格。召回先找相关候选，再检查条件差异；条件未知时保留未知，重新验证。

**怎样验收。** 同一方法在不同接收端契约、用户群或版本中可能产生相反结果。测试模型是否能避开文字高度相似但条件不兼容的经验，同时找到措辞不同但结构相同的可用经验。与 0.7.1 词面召回在相同上下文预算下比较。

**现状。** 已保存引用版本与适用理由；条件主要仍是自由文本，尚无系统化的条件匹配与适用性校验。

## 3. 优先经验回放：按未来决策价值分配注意力

**来源与边界。** Mattar 与 Daw 的规范性模型用未来决策的需要程度和回放可带来的收益解释经验访问优先级，即 need 与 gain 的结合。它在空间导航模拟中解释多种海马回放现象，并不提供一个现成的、适用于任意项目文本的高效检索器。[Nature Neuroscience，2018](https://www.nature.com/articles/s41593-018-0232-z)

**工程提案。** 在词面召回之后，优先检查可能改变候选行动排序的经验：即将依赖的前提、最近被反证的判断、潜在代价大的重复错误、与本次条件冲突的旧成功。对没有新证据、且不会影响当前选择的重复复盘降低投入。相关、可信、适用和有决策价值应分别判断。

need × gain 可作为设计解释，暂不把模型随口报出的概率或收益当作真实数值。先使用可审计的依据与有界候选，逐步通过实际后续结果校准排序。

**怎样验收。** 在大量无关新记录中放入一条低词面相似度但会改变选择的反例；比较最近记录、词面召回和决策价值重排。记录重复错误、决策改变是否有依据、检索/推理成本和实际结果；只引用更多记录不算成功。

**现状。** 0.7.1 有词面和 feature 关联排序，有引用追溯；尚未实现 need/gain 优先回放。

## 4. 预测误差与变化点：辨别噪声、错误假设和环境变化

**来源与边界。** Nassar 等人的行为实验与近似贝叶斯模型区分环境随机性和变化点，对意外结果采取不同程度的信念更新。该研究支持按不确定性调整更新，而非所有意外都等价；不能据此把 LLM 自报信心当作经过校准的概率。[Journal of Neuroscience，2010](https://pmc.ncbi.nlm.nih.gov/articles/PMC2945906/)

**工程提案。** 重要行动先保留可观察的预测、适用条件与观察期限；拿到反馈后比较原预期，并区分：

- 数据没有到齐或采集故障，需要修复观察条件。
- 普通波动，暂不足以改变方向。
- 结果反驳原解释，需要比较竞争解释或改变方法。
- 版本、对象或环境已经变化，需要重新判断旧经验适用性。

缺少数值依据时可记录定性预测和能推翻它的观察，不虚构置信度。失败归因由 Codex 提出，框架保留原预测、证据和理由；尚未观察到效果不自动归类为无效。

**怎样验收。** 引入延迟反馈、随机噪声、稳定分布中的坏样本和真正的环境切换。分别测量误报切换、发现切换所需时间、无效重试和资源消耗。重点观察能否适时调整，也能否在没有足够新信息时保持安静。

**现状。** 0.8.0 已实现事前观察来源/窗口与数值字段核对，定性结果由 Codex 解读；复盘区分待观察、采集、执行、假设、环境及原因未知。适用条件的比较和原因解释仍由 Agent 提供，未实现统计变化点检测、因果归因或概率校准。

## 5. 信息价值与元推理：决定先做事、先调查还是停止

**来源与边界。** 信息导向采样研究如何在部分反馈下平衡获得收益和获取决策相关信息；元推理研究如何把计算本身视为有成本的选择。两者适用的问题假设不同，不应合并成一个未经定义的万能分数。[Russo 与 Van Roy](https://arxiv.org/abs/1403.5556)，[Hay 等](https://arxiv.org/abs/1207.5879)

**工程提案。** 比较候选行动时，除了直接改进，也允许选择获取关键事实、补齐必要能力和等待。调查前说明哪种可能结果会改变下一步选择；如果任何结果都不会改变选择，应重新检查调查价值。继续推理、检索和建设工具同样消耗预算。

探索保留开放空间，但需解释它与目标或未来工作能力的关系。资源边界按项目授权与实际成本执行，避免用产生文档、运行次数或新技能数作为内在奖励。对无法可靠量化的价值保留范围或定性理由，避免任意拼接带权评分。

**怎样验收。** 提供一个昂贵实现、一个廉价且能区分关键解释的检查，以及一个不断生成新奇数据却不能帮助选择的来源。观察是否选择有用信息，是否在边际价值降低后停止。元推理不能靠额外无限预算取得优势。

**现状。** 候选种类、投入描述、停止条件和轮次限制已实现；信息价值评估及按实耗资源管理仍不完整。

## 6. 组合性与技能形成：学习可重用的结构

**来源与边界。** Bakermans 等于 2025 年结合计算模拟与啮齿动物海马记录，研究由已有组成部分构建新状态表示、借助回放支持泛化的机制。结果涉及所研究的可组合环境，不能直接推广为任意经营任务都能零样本迁移。[Nature Neuroscience，2025](https://www.nature.com/articles/s41593-025-01908-3)

工程参照 Voyager 将可执行技能、环境反馈与自主课程结合，并在 Minecraft 中验证复用。它提供了实现线索，游戏中的进展指标与软件、运营目标仍需分别设计。[Voyager](https://arxiv.org/abs/2305.16291)

**工程提案。** 从实际有效的尝试中提取小而可组合的方法，保留输入输出、前置条件、依赖版本、失败方式和验证入口。技能是否晋升取决于在新的合适条件下能否复用，而非一次执行通过。组合之前检查前置条件和副作用；出现反证可降级或停用。

例如 0.7.1 隔离验收中的“稳定批次标识”只验证了进程内重试。它不能直接升级成“订单导入可靠”的通用技能；需要与持久恢复、回执核对等方法分别验证后组合。这个例子说明机制，不能硬编码成所有项目的任务序列。

**怎样验收。** 在相同结构、不同表面内容的任务上验证迁移，再改变一个关键前置条件测试拒绝错误复用；使用未参与提炼的测试集。同时计算维护技能的成本，停用不再有价值的方法。

**现状。** 原生 Codex 能写工具，Morrow 保存相关工作；技能自动提炼、验证晋升与组合管理尚未实现。

## 7. 因果判断与可靠外部反馈：区分做了什么、改变了什么

**来源与边界。** 因果推断将观测到的关联与干预效果区分开来，需要明确比较对象和识别假设。[Hernán 与 Robins](https://www.hsph.harvard.edu/miguel-hernan/wp-content/uploads/sites/1268/2024/04/hernanrobins_WhatIf_26apr24.pdf)

Reflexion 展示了语言反馈和经历记忆支持后续尝试的方式；CRITIC 在研究任务中强调借助工具反馈进行纠正。它们支持做有反馈的循环，但不证明当前模型仅凭重复自评就会可靠进步。[Reflexion](https://arxiv.org/abs/2303.11366)，[CRITIC](https://proceedings.iclr.cc/paper_files/paper/2024/hash/fef126561bbf9d4467dbb8d27334b8fe-Abstract-Conference.html)

**工程提案。** 测试通过、发布成功和用户行为变化分别记账。评估业务改进时保留版本、观察窗口、样本条件、比较依据、可能的混杂因素和不能牺牲的约束。数据不足时可以报告已观察的变化，并保留因果结论未知。固定原始目标和评价定义，防止通过改口径把失败变成功；需要调整目标时向用户说明依据。

**怎样验收。** 提供“指标上升但来自用户群变化”“转化上升但退款恶化”“测试通过但未部署”等场景，验证是否避免错误归因和只优化局部指标。以真实工具、回执或独立反馈检验模型解释，不以模型自己赞同自己作为验收。

**现状。** 证据来源、发布版本与原始预期保护已存在；完整的实验设计、归因判断和目标约束评估仍待补齐。

## 8. 开放式探索与质量多样性：自己发现下一批值得解决的问题

**来源与边界。** MAP-Elites 保存不同特征区域内表现好的解，形成多样化方法集合；POET 同时生成挑战、改进解法，并在挑战间迁移已有解法。二者分别提供保留不同路线和生成学习课程的算法依据。POET 在所研究的模拟环境中展示了直接优化难以获得的解，不证明任意商业目标都能自动涌现出成功路径。[Mouret 与 Clune，2015](https://arxiv.org/abs/1504.04909)，[Wang 等，2019](https://arxiv.org/abs/1901.01753)

**工程提案。** 对同一目标保留少量具有实质差异的候选路线，并从失败、能力缺口和新观测中生成可验证的子问题。路线差异要体现在干预对象、工作方式或资源条件上，不能只换措辞。保留已有尝试的真实结果，让一个方向获得的能力有机会帮助另一个方向；暂时没有直接收益的尝试，也可以因可验证的后续用途成为继续探索的依据。

例如，在隔离实验中得到的故障复现能力，后来可能用于自动验证新版本和解释流失现象。框架应允许这种用途被发现，但不能预先断言它能带来营收。候选和实验共享项目预算；无相关性、长期没有进展或被反证的路线需要停用。新问题数量、档案规模和新奇程度都不能替代目标结果。

**怎样验收。** 构造存在局部最优、需要一个中间能力才能突破的项目；在相同总预算下比较仅保留当前最佳路线、保留多样路线、再允许生成与迁移子问题的结果。检查跨路线复用是否发生、是否有证据，以及维护候选是否浪费资源。环境由测试准备者独立设置，避免模型同时定义挑战和宣告挑战成功。

**现状。** 已有候选行动与决策历史；持续维护多样路线、自动生成并验证挑战、按实际迁移价值保留尝试尚未形成机制。

## 9. 时间抽象与分层决策：让长期方向跨越多次运行

**来源与边界。** Sutton、Precup 与 Singh 的 options 框架把持续一段时间的闭环行动表示为可开始的条件、执行策略和结束条件，并纳入强化学习的规划与学习。它提供时间抽象的形式基础；Morrow 借鉴这种结构，不等于已经具有该论文假设下的状态模型、奖励函数或学习算法。[原论文，1999](https://incompleteideas.net/609%20dropbox/other%20readings%20and%20resources/Options.pdf)

**工程提案。** 将用户长期目标、当前阶段判断和正在执行的有限尝试关联起来。阶段由项目认识形成，可以调整，不预设“开发、运营、增长”的固定流水线。一次运行结束时保留当前尝试及下一次可继续的条件；新事实、用户指导、停止条件或资源上限可以触发中止和重选。下次唤醒先判断现有承诺是否仍有效，减少无依据地从头规划。

“理解首次使用的阻碍”可以持续跨越若干调查与验证，但“完成某个检查”不能自动证明上层目标改善。已经成熟的方法可作为较大的行动单位被调用，内部工具步骤仍交给原生 Codex 管理。

**怎样验收。** 让一个方向跨越多次唤醒和重启，检查能否延续未完成工作；中途改变关键前提，检查能否停止不再适用的方法。评价方向反复、重复调查、无效坚持及最终效果，不能只验证计划树是否生成。

**现状。** 持续原生任务、项目目标、有限尝试与停止条件已存在；显式的阶段依赖和跨层结果核对仍待验证。

## 10. 双环学习：复盘做法，也复盘支配做法的前提

**来源与边界。** Argyris 的组织学习研究区分在既定政策内纠错，以及重新审视支配行动的政策和目标。它是组织学习的概念框架，不是给 LLM 多加一轮反思就会改善的算法保证。[作者原文的出版方摘要，1977](https://store.hbr.org/product/double-loop-learning-in-organizations/77502)

**工程提案。** 复盘允许分别修改执行办法、对项目的解释和框架使用的方法。例如连续优化引导仍然无效，可以检验“用户需要的核心结果是否选错”“阻碍是否实际发生在数据接入”“观测是否遗漏了关键人群”。失败后增加投入只是一种候选，重新诊断也应参与选择。

同样审查系统自己的工作方法：某个技能、召回方式或调度安排是否持续制造错误。改进提案要有前后对照，保持原始记录可追溯。用户的目标和授权边界继续有效；Codex 可在范围内修订假设与策略，涉及改变用户目标的建议需明确交给用户决定，不能借复盘改写成功标准。

**怎样验收。** 提供一个执行正确但根本假设错误的场景，以及一个根本假设正确但实现有缺陷的场景。检查是否能选择恰当的修正层次；将调整机制本身的收益与额外成本一起测量。

**现状。** 0.8.0 已记录诊断与调整层次，重新判断假设时要求先持久化认识修订并引用版本；跨尝试识别共性错误、评估自身工作方法的长期收益尚未验证。

## 11. Goodhart 效应：持续检查指标是否仍代表用户要的结果

**来源与边界。** Manheim 与 Garrabrant 区分因噪声、极端优化、因果关系和对抗行为引起的代理指标失效。这是分析不同故障的理论分类，不是一条可以直接代入的通用修正公式。指标被优化后失真也可能发生在执行者没有欺骗意图时。[原论文，2018](https://arxiv.org/abs/1803.04585)

**工程提案。** 明确用户要的结果、可观测的代理指标、不能牺牲的条件和仍无法观测的部分。例如完成引导、付费、留存和退款之间的关系需要实际验证；增加完成率本身不足以判定所有目标都改善。评价口径、样本范围和版本需要留存，改动口径必须能够与旧口径对照，不能覆盖原评价。

对存在取舍的结果分别报告，不随意加权成一个“成功分”。把验收依据与实施记录分开核对；模型自行生成的测试、模拟用户反馈和真实用户效果分别标记。可使用未参与优化的检查或外部观测，但不把单一测试集误当作永远可靠的目标替身。

**怎样验收。** 刻意设置“跳过关键步骤使完成率上升”“关闭测试使通过率上升”“短期付费增长但退款增加”等诱导；检查系统是否识别损害、保留未知和真实取舍。只拒绝明显作弊还不够，也要检查善意优化造成的指标脱节。

**现状。** 0.8.0 保存不可覆盖的原始核对项，约束未获支持时不能报告本次预期达成，改变比较条件时保留结果未知。能否选出真正代表用户目标的指标、发现遗漏约束，仍需 Codex 判断与独立评估。

## 12. 黑板架构与按条件协调：让新发现带动相关工作

**来源与边界。** Hearsay-II 用共享黑板保存中间假设，由状态变化激活适用的知识模块，再调度有希望的工作。论文也讨论了把所有内部运算都强行放进黑板的效率问题。这是有任务实验的经典 AI 架构，不意味着所有系统都应增加多个角色或全局调度每个工具步骤。[Erman 等，1980](https://mas.cs.umass.edu/Documents/Erman_Hearsay80.pdf)

**工程提案。** 复用项目现有共享记录，关联事实、假设、feature、依赖和待满足条件。一个观测若改变了另一项工作的前提，就让受影响的工作重新进入候选；原判断不再有效时传播失效依据。各频道围绕同一事实与同一 feature 协作，避免复制卡片和重复调查。

例如某项诊断能力完成后，原先因缺少证据而等待的判断可以继续。需要继续的是关联工作，不必唤醒项目所有频道。共享记录保留来源、版本、占用和完成状态；全量运行 I/O 继续按既有规则落库，原生执行内部步骤不增加逐步黑板协调。

**怎样验收。** 在隔离项目里让两项责任依赖同一份证据，再加入证据修订、重复事件和恢复重放。检查只唤醒相关工作、不会重复副作用、不会使用失效依据，以及减少的重复劳动能否覆盖协调开销。

**现状。** 项目统一看板、来源引用、反馈唤醒、项目串行及版本检查已具备；0.8.0 将约定来源的新证据与观察期限接入相关行动的复查。更一般的跨工作依赖传播仍未完整实现。

## 后续实现优先级与已落实部分

1. **条件化预测和结果核对：0.8.0 已落实基础。** 在现有 `decision.choose/review` 旁补清楚“期待观察什么、什么时候、什么条件下、什么会推翻预期”，以真实反馈指导改向。这让持续工作有可靠的学习信号。
2. **再补情境与决策价值驱动的召回。** 保留当前检索作为基线，增加条件核对、反例优先与有限重排，验证它是否确实减少重复错误。
3. **最后增加有预算的巩固与方法组合。** 从真实轨迹提炼候选规律、构造留出验证，按效果晋升、修订或停用；与有价值的在线工作竞争同一资源预算，手动暂停仍然有效。

本轮补充的第 8–12 节不意味着要额外建设五套子系统。先把双环学习与代理指标检查融入现有选择和复盘；在可信反馈基础上，用一个有界的多路线探索实验验证能否发现更好的工作方向。时间抽象和黑板机制优先用于修复实际出现的连续性与协调问题，再根据证据决定是否扩展。具体顺序是工程建议，不能仅凭理论名称决定增加复杂度。

所有工作继续落到同一原生任务、项目统一看板与 SQLite。用户界面展示当前工作、依据、预期、真实结果和需要确认的发布；理论名称和内部评分不变成用户配置负担。

## 如何决定是否保留一项理论带来的改动

沿用陌生隔离项目，但把目前的单次演示扩展为可重复比较：固定初始状态、原生模型配置、权限、工具和总预算，对比当前版本与新增机制；使用不同项目和多次运行，公开失败及波动。测试集应包含延迟效果、噪声、环境切换、过时记忆、条件不匹配、重复失败、重启恢复和代理指标误导。

评价有效目标结果、重复错误率、错误归因、调整延迟、人工介入以及实际资源成本。尚不能准确计量的成本明确缺失，不拿轮次冒充 token 或费用。移除一个机制后进行消融，检查改善是否仍存在。只在收益能覆盖复杂度和运行成本时保留该机制。

最初研究轮次仅整理理论与验证路线。用户随后要求实现，0.8.0 落实了上述预期核对与判断修订基础；其余研究提案仍不能作为已实现或已验证能力报告。
