# Project work loop (0.6.0)

`POST /api/agent` uses a private, expiring run grant distinct from the desktop credential. The grant identifies one project, channel and active run. `context` and `evidence.read` are read operations. Mutations require a stable `requestId`; the mutation and cached result commit in the same SQLite transaction. Replays return the same result, different payloads under the same ID conflict, and fresh operations after the run ends are rejected.

Operations: `feature.upsert`, `evidence.record`, `evidence.capture`, `learning.upsert`, `watch.create`, `watch.cancel`, `wait`, `release.propose`. Item and learning updates use revisions. Evidence distinguishes agent statements, actual file capture and HTTP capture. `context` abbreviates long evidence with `truncated:true`; `evidence.read` returns the preserved content.

`GET /api/projects/:id/work?itemId=...` returns shared observations, learning, watches and releases. `POST /api/releases/:id/review` accepts the desktop credential, exact `reviewHash`, `approve|reject`, and optional feedback. The agent grant cannot call this endpoint. `POST /api/releases/:id/reconcile` checks an uncertain outcome without resending publication.

Release preparation copies a project-contained artifact (up to 8 MiB) into private storage and binds its SHA-256, target, checks and review text. The HTTP adapter sends `POST {releaseId,reviewHash,artifact:{name,sha256,bytes,base64}}` with `Idempotency-Key: releaseId`. A receipt must match `releaseId` and `artifactSha256` and report `status: published|failed`. The GET status endpoint receives a `releaseId` query parameter and returns the same receipt. A lost or mismatching response stays unknown; recovery queries status rather than reposting.

HTTP JSON observations are bounded to 512 KiB with a 10-second timeout, explicit JSON Pointer, at least 30 seconds between polls and up to 50 active monitors per project. `continuous` defaults to true: after a condition is triggered or a review deadline expires, changed values still produce evidence and wake the enabled source channel. Identical values stay quiet. `continuous:false` makes an observation end after its condition/deadline. Cancellation or pausing the channel stops scheduled collection. Waits may refer to another channel's source in the same project.

`loop_grants`, `loop_calls`, `loop_evidence`, `loop_learning`, `loop_watches`, `loop_waits`, `loop_releases` are additive SQLite tables. Native executions retain their exact task/turn IDs. Scheduled turns use native automatic review and the saved workspace scope, and never steer an unexpectedly active user turn. Shared-host selection first preserves a verified launch, otherwise probes loaded task IDs without resuming candidates; ambiguous ownership fails explicitly. Local projection revisions have a fresh epoch for each shared connection, so daemon restarts cannot discard the new stream as stale.
