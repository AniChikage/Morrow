# 0.7.0 自主判断与经验复用验收

日期：2026-09-08。此版本实现项目认识、行动选择、复查和历史检索的基础机制；不宣称任意项目自主经营或自动技能库已经完成。

## 实现与机制检查

- 新项目只创建一个暂停的「自主推进」频道，允许在自己的工作区修改，每日最多 32 轮；已有设置不迁移。
- 认识保留事实/假设/未知/能力/约束、依据、适用理由和复查方法；每次修改有独立版本。行动保存候选方向、取舍、原目标、预期、验证及停止条件，复盘不能覆盖原预期。
- 新指导、相关反馈、目标或依据变化、复查时间及尝试投入触发重判。当前选择需要复盘时，工作接口拒绝继续推进 feature 或准备发布，仍允许调查、记录与复盘。此限制不替代原生执行权限；每日调度上限仍独立执行。
- 观察与停止类选择不会因每次观察的轮次计数而持续唤醒。手动暂停保留；跨频道共享记录，同一 feature 不重复占用；重启后保留选择、版本、信号与投入记录。
- 历史检索覆盖当前摘要以外的旧认识、复盘及学习记录；完整读取、过期记录身份、分页、跨项目拒绝和幂等重试均有隔离测试。

检查结果：`npm run typecheck` 与服务严格类型检查通过；`npm test` 为 91 项通过、1 项条件跳过；`npm run test:ui` 为 148 项通过；`npm run build:app` 和安装包深度签名检查通过。最后一次服务调整另外重跑了全部 8 项自主判断测试。条件跳过项需要显式提供原生运行时二进制，不应计入通过数。

## 真实 Codex 隔离实验

使用陌生的 Fieldnote 小型原型，只提供项目目标、源码、未验证的旧团队笔记、本机反馈地址和隔离权限。目标是「帮助目标用户从自己的材料中得到可信、可交付的结论，依据实际反馈持续改善」。没有告诉 Codex 应该修复什么或怎样改进。

同一原生任务：`01a07fbd-ffff-7de3-ab70-27969c68336d`。项目和服务均使用独立临时目录，没有运行用户项目、发送外部消息或操作生产发布。

第一轮：旧笔记猜测需要重写注册，实际隔离反馈显示 98/100 注册成功，61/100 不知道应准备哪些材料。Codex 根据反证降低注册方向优先级，记录三种候选方向，选择材料就绪检查与可追溯简报，建立一个共享 feature，并实现和通过 6 项行为测试。它将「本地行为已验证」与「业务效果未知」分别记录，复盘结论为 `inconclusive`，随后自己选择观察新 cohort。

第二批反馈来自不同的人工辅助起步条件：90/100 生成结果，但只有 19/100 认为有用，主要问题转为缺少原始证据和核验成本。持续观察采集到变化后，调度器自动唤醒同一原生任务。Codex 读取完整证据、复盘观察、将旧的当前阻塞判断标为失效，并明确不同条件的数据不能归因于工作区修改；随后沿用原 feature，选择独立证据审计和带引用的 Markdown 交付物。

第二轮完整结束：证据审计实现后，Codex 自己发现使用者仍缺少从材料文件获得交付物的入口，继续比较方向并实现零依赖本地 CLI。最终 18 项测试覆盖材料不足、引用核验、证据篡改/删除/重复、文件输入输出、防止覆盖和错误路径，并实际生成带引用的 Markdown 示例。验收者将最终源码复制到独立目录，重新运行这 18 项测试，全部通过。两轮始终维护同一个 feature；模型最后判断继续增加功能缺少依据，选择等待下一批反馈，未编造业务提升或发布端。

验收加速说明：Codex 自己选择了 600 秒反馈采集间隔。测试操作者仅在隔离数据库中将下一采集时刻提前一次；没有修改模型的目标、方向、预算、策略或下一步，没有发送继续工作的提示。采集、生成反馈证据和唤醒由正常服务机制完成。

本实验运行期间补充的摘要限长、安静观察和工作接口复查拒绝规则，由隔离服务测试验证；真实模型实验主要验证自主理解、选择、复盘与反馈后的改向，不能据此声称覆盖了每个拒绝分支。
