# 开始使用 Morrow

[文档首页](README.md)

## 从源码安装

需要 macOS 14+、Node.js 24+、npm 和 Xcode Command Line Tools。使用 Codex 时，按频道选的传输方式准备其中一样：走 **Codex App 任务**（默认）需要安装并登录 Codex Mac App；**直连 Codex CLI** 需要安装 Codex CLI 并在终端 `codex login`，不需要 App。Morrow 不要求另填模型 API Key。

```bash
git clone https://github.com/AniChikage/Morrow.git
cd Morrow
npm ci
npm run build:app
bash scripts/install-app.sh
open "$HOME/Applications/Morrow.app"
```

构建输出为 `dist/Morrow.app`，安装默认写入 `~/Applications/Morrow.app`。安装器先复制并校验完整签名，再替换应用；回退副本只在安装期间保留，成功后清理。也可给安装脚本传入其他目标目录。构建会准备并校验 Node 24 运行时，安装后的 App 自带该运行时。当前产物使用本机 ad-hoc 签名；正式对外分发还需要 Developer ID 签名与 Apple 公证。

## 第一个项目

1. **接入项目并写项目说明**。在侧栏或标题栏点「接入项目」，选择现有目录，写下持续目标，并在「项目说明」里写下你知道而仓库里没有的东西（目标与成功标准、目标用户与场景、当前阶段与已知问题、优先级与不做的事、资源与入口、约束与红线、需要你决定的事；「插入模板」会填入这些标题）。Codex 每轮都会读取它并优先于自己的推断，但不会修改；之后可在项目页的「项目说明」标签随时修改，改动后进行中的判断会被要求重新评估。接入时还可以选择这个项目的默认运行时（Codex，或用本机已登录 CLI 的 Claude Code 与 Trae）。新项目会准备一个暂停的「自主推进」频道，每日最多 32 轮。接入本身不会启动执行。
2. **新建频道，并为 Codex 选一种执行方式**（需要另一条工作方向时）。在侧栏的项目上点「新建频道」，填名称和工作方向。选 Codex 时，「工作设置」里的**执行方式**决定这条频道怎么找到 Codex，两条路后面的步骤不一样：

   - **Codex App 任务**（默认）：轮次进入 App 中一条你指定的任务。应用内浏览器、Computer Use、App 动态工具和 App 内审批只有这条路有，代价是 App 必须装好并保持运行。工作接口在 App 轮次里走任务内 HTTP；CLI 轮次另有主机 MCP。模型、工具与任务权限都在 Codex App 中管理，频道默认沿用该任务的权限与审批设置。Morrow 不能后台创建 App 任务。
   - **直连 Codex CLI**：每轮起一次本机 `codex exec`。准备工作只有一件——装好 Codex CLI，在终端 `codex login`；不需要装 App、不需要在 App 里建任务、不需要关联，也不需要让 App 一直开着。没有应用内浏览器、Computer Use、App 动态工具和 App 审批；沙箱内命令仍然不联网。有 grant 的一轮通过主机侧 Morrow MCP 调用工作接口（含 `release.propose`），凭证不进提示词；**不能批准上线**（批准仍在桌面），`evidence.native` / `execution.prepare` 在没有 App 任务时返回 409。发布级复核对这条路接受 file/http 采集证据，由独立复核者在隔离检出里重跑检查，不伪造 native execution。权限与 Claude Code / Trae 同级，默认工作区写入，可收紧为只读，没有「沿用 App 原生权限」这一项。两条路花的是同一个 Codex 账号的额度。

   频道创建后保持暂停。执行方式之后还能在「调整方向」里改，但轮次进行中不能改，已经关联了 App 任务的频道也不能改（新建一条频道即可），因为两边的会话 ID 不通用。

3. **在 Codex App 新建任务，再回到频道关联**（只有走 App 任务的频道需要，直连 Codex CLI 的频道跳过这一步）。在 App 为同一项目目录创建任务，发送首条消息并保持打开，然后在频道页点「关联 App 任务」。运行时页会核对：App 已安装 → App 已连接 → 任务已关联 → 关联任务可用。Morrow 不再安装启动转接程序，也不直接新建 App 任务。App 必须保持运行；需要完整访问时请在 App 中设置。直连的频道不出现在这份核对和「去关联任务」的候选里；它缺的是本机的 Codex CLI，频道页会直接说要装 CLI 并 `codex login`。
4. **点「继续工作」**。Codex 结合项目目标与现状选择下一步。走 App 任务的频道通过项目工作接口维护判断、看板和证据；直连 Codex CLI、Claude Code 与 Trae 在有 grant 的一轮同样走工作接口（主机 MCP），没有 grant 的一轮仍可用可选报告写看板。想给自己留出 Codex 额度时，在设置（`⌘,`）的「保留给自己的额度」里填一个窗口和百分比；想限制某个项目时，在项目属性栏的「额度」里设上限（按 Morrow 归因的估算）。达到后 Morrow 不再发起新的自动轮次，频道显示「等待额度重置」。同一个按钮也用来暂停。
5. **回答提问**。Codex 提出问题时，频道页的「需要你」区会显示问题和答题框，项目页属性栏的「待回答」会列出所有等待回答的频道。走 App 任务的频道在这里直接答，审批和追问则在 Codex App 里处理，频道页只提示有哪些在等你，并提供「在 Codex App 中打开」；频道页不镜像对话，也不从 Morrow 发送消息或图片，完整对话在 App 里看。Claude Code、Trae 和直连 Codex CLI 的频道也会在「需要你」里显示问题：这类轮次说自己需要人时会停下自动调度，把那一轮的提问按原文显示出来，同样出现在项目页的「待回答」里。区别是那里只读——这类频道没有原生对话可答（也就没有 App 审批这一说），答案写在页面底部的留言框（见第 7 步），再点「留言并运行一轮」把它交给下一轮；只留言不会开始运行，回答也不会重新打开自主运行，要恢复自动调度点「继续工作」。
6. **审阅上线材料**。需要上线时，到项目页的「上线确认」查看具体改动、预期收益、证据、回退方案和上线后的观察计划，再决定是否上线。上线目标是你自己提供的 HTTP 接收端，或是你写好并提交在项目里的脚本（`local-script`，例如 `scripts/release-local.sh`）：脚本内容在提议时被封存，页面上可以逐字读完将要执行的内容，只有你确认后 Morrow 才以固定的最小环境执行那份封存副本。
7. **给没有 App 任务的频道留言**（Claude Code、Trae 和直连 Codex CLI）。这类频道的页面底部有留言框，也是你给它下达指令的唯一入口：写下补充背景或下一轮的方向，点「留言」，它会在下一轮开始时随上下文交给 CLI，列表里会写明每条是「等下一轮读取」还是已在哪一轮被读取。留言本身不会开始一轮；要它立刻处理就点「留言并运行一轮」。
8. **装上新版本后自动切换**。检测到新版本时，窗口顶部会出现一行提示；Morrow 等当前工作结束再自动切换，也可以点「立即重启」，有工作在跑时这个按钮不可用。

欢迎页提供明确标注的示例工作区，示例频道不会执行。`⌘N` 打开项目，`⌘K` 搜索，`⌘,` 打开设置，`⌘B` 切换侧栏。
