# 0.8.0 预期核对与修订判断验收

日期：2026-09-08。本轮将理论提案中的事前预期、反馈核对和修订认识落实为现有闭环的增量。策略仍由 Codex 选择，用户不需要填写实验表格。没有实现自动因果推断、模型权重训练、完整技能进化或 POET 多路线探索。

## 已实现的机制

- 新行动通过 `decision.choose.expectations` 事先保存 1–8 项可观察预期，至少包含一项结果；允许另设不能牺牲的约束。保存适用范围、文件或 HTTP 观察来源、验证方法、反证条件及观察窗口。停止方向可不设置预期。
- 选择同时保存原始目标、预期、认识版本和证据位置；不能在复盘时覆盖。已有历史决策保留旧协议，不补造历史预期或观测。
- 复盘必须逐项说明结果并引用事前约定来源的新采集证据。旧基线、同毫秒但先于选择入库的证据、跨来源引用、Agent 自述，以及遗漏窗口内最新观测均有对应检查。缺少有效观测只能保留未知。
- 可选 JSON 字段规则支持 `gte`、`lte`、`equals`，严格检查标量类型并保存实际值。缺失、不可解析或类型不符的字段不能算成功或失败；文字判断不能覆盖字段核对。定性核对明确标为 Codex 解读。
- 全部结果和约束均有支持，且条件被判断可比，才允许记录本次预期达成。约束恶化不能被其他成功指标抵消。环境变化、数据未到和测量问题保留不确定性，原因不明不等于观察结果必然未知。
- 选择重新判断假设时，必须先保存新增或修订的项目认识，再引用版本；复盘解释、适用条件和反证也进入既有经验召回。
- 相关新证据和观察期限进入复查信号。HTTP 数据即使与旧基线相同，也可为新行动保存一次窗口内采样；其他规则字段变化会被记录。重复未变化或无效对象字段不会每轮制造证据，手动暂停保持有效。
- SQLite 保存以上记录，继续关联原生任务、运行、项目、频道及共享 feature。复用已有 JSON 记录和版本表，新增字段兼容旧数据。
- 项目「当前判断」和 feature 内复用紧凑的「预期与实际」展开区，展示原预期、实际字段或定性说明、原始证据、条件判断和调整方向。

协议见 [项目工作接口](PROJECT-WORK-CONTRACT.md)，理论与实现边界见 [认知机制参考](COGNITIVE-ARCHITECTURE.md)。

## 真实原生 Codex 验收

使用独立临时目录、SQLite 和服务创建陌生的 ParcelNotes 交接导出原型。输入为初始源码、基础测试、明确标注为模拟的反馈、可用资源和边界；目标是「让交接人员可靠地交付完整信息，减少导出后回头找原文核对的工作」。没有指明应修复的代码或规定策略。

实际模型：`gpt-5.6-sol`。原生任务：`01a0804d-e8ba-7da3-a58a-3b411928c85f`；Morrow 运行：`8f903b01-1fca-46aa-a01e-811318f20e31`。一次调度完成后暂停隔离频道。

实际观察：

1. Codex 从模拟反馈与源码发现 `body.slice(0,80)` 会丢失交接要求，现有仅检查记录条数的测试不能发现内容损失。
2. 自主比较移除截断、增加截断标记、调查长度上限三个方案，选择小范围修复，建立同一 feature 并保存认识。
3. 在修改前保存两个定性预期：正文完整保留，以及记录数量、顺序、ID 和输入不可变性保持。
4. 移除截断、补充回归测试，真实运行 `node --test` 得到 3 项通过。夹具由输入 150、输出 80 字符变为输入 150、输出 150 字符，末尾要求保留。
5. 采集文件证据并逐项复盘，更新同一 feature；明确范围仅为本地实现和隔离夹具，真实用户回查率未知。
6. 保存交付包和校验和；因夹具没有发布端，未虚构端点或执行发布。最终保留资源缺口，由验收脚本暂停并关闭隔离服务。
7. 将最终项目复制到独立目录，再次执行其 3 项测试，全部通过。

本次模型将预期来源选为测试定义文件，复盘属于 `checkedBy: agent` 的定性解释；测试定义本身不能机械证明命令实际执行通过。原生执行记录和独立重跑另外核实了测试结果。数值规则、假设被推翻后的认识修订等分支由服务测试覆盖，本次真实模型运行未覆盖这些分支。

运行中出现过一次接口连接失败和一次 feature 版本冲突，模型重试读取后自行恢复。最终运行状态为 `completed`；旧版文本看板报告为 `missing`，实际 feature 更新来自工作接口，不将缺少旧报告误计为运行失败。没有宣称完成上线或真实业务收益验证。
