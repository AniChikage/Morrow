# NoHuman 0.6.0 验证记录

验证时间：2026-09-07 至 2026-09-08，macOS / Apple Silicon。

## 实现

保留已确认的灰白 Electron/React 界面。Codex 在同一原生任务中维护项目唯一看板、证据、判断和尝试，准备封存发布版本；用户在项目「上线确认」审阅变更、依据、预期收益、验证、风险、回退与观察计划。确认后执行发布并核对同一版本回执，反馈继续关联原 feature。

工作接口、调用回执、等待、观测和发布记录均持久化到 SQLite。原生任务提供按运行与项目限定的工作凭证，不能调用人工发布确认接口。HTTP 发布状态不确定时只核对回执，不重复发送。持续反馈在复查到期后仍接收变化，支持显式取消、一次性实验与频道暂停。

## 真实 Codex 的隔离验收

原生任务 `01a07c7e-0060-7282-9090-0ca0c685a57e`，运行时报告模型为 `gpt-5.6-sol`。四个轮次沿用同一个原生任务；仅运行临时的隔离项目，没有执行用户已有项目。

1. 只给出改善首次核心操作的目标、代码文件及可用本机反馈/发布资源，没有直接指出修复项。Codex 自行从模拟访问发现国际化名称被拒绝及空白名称问题，建立一个 feature、记录依据、修复并通过 5 项回归测试。
2. Codex 提交封存发布说明并等待确认。确认前接收端仍运行旧版本。测试端仅确认本机隔离版本后，发布回执匹配封存 SHA-256；同一 Codex 任务读取到 224/224 次新版本模拟访问成功，将成效判断更新为证据支持，并建立后续监测。
3. 到期复查继续沿用原 feature 和任务。验收发现旧报告误暂停、重连序号及到期后停止收集的问题，修复后执行回归与原生恢复验证；没有把这几处最初失败描述为一次无中断通过。
4. 在独立模拟访问中新增印地语名称 `टीम`，不向模型发送修复提示。持续反馈采集到完成率回落和错误，自动唤醒同一任务。Codex 重新打开原 feature，发现遗漏 Unicode Mark 类别，把原判断改为证据不足，修复并通过 6 项测试，提交第二个具体版本等待确认。

最终仍只有一个 feature、两个发布版本。第一个已发布；第二个未确认，接收端没有第二次发布回执，仍运行第一个版本。验收结束后暂停并关闭临时测试环境。

这是小型可控场景中的真实模型与机制验证；模拟完成率不代表真实用户、收入或生产稳定性。实际项目仍需提供或在已有授权内建立其 HTTP 发布端、回执查询端和 JSON 反馈来源。本机服务在 Mac 休眠时不能执行或采集。

## 界面与安装

通过 CUA 检查安装版项目入口、独立的上线确认页，以及真实模型生成的功能和两次发布说明。检查了验证来源、回退说明、预期/实际收益区分与确认按钮。早期隔离界面流程实际点击确认并验证了发布回执；第二个真实模型版本保持待确认。

安装位置：`~/Applications/NoHuman.app`，版本 0.6.0。安装内容与最终构建的 renderer、闭环服务和原生连接模块一致，签名有效，SQLite `quick_check` 为 `ok`。升级保留已有 3 个项目、7 个频道、目标、权限、原生任务绑定与暂停状态；没有启用任何原先暂停的用户频道。安装后的原生后台连接和后台恢复能力均为真实就绪状态。
